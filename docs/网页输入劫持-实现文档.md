# 网页输入劫持：点中输入框 → SDK 输入页 → JS 回填

> 状态：已实现并验证（2026-09）
> 涉及提交：`feat(keyphone): hijack web input fields into SDK input page with JS refill`

## 1. 要解决的问题

按键机（320×480，无虚拟导航键）上用 WebView 浏览网页时，点中网页输入框会拉起系统输入法，出现经典冲突：

- IME 悬浮窗遮挡大半个 WebView，焦点在 IME 与网页光标之间来回抢；
- 输入法窗口与 WebView 的窗口焦点竞争，光标丢失、按键分流到错误目标。

## 2. 方案总览

网页文本输入**完全不走系统输入法**，改为两段式：

```
光标点击输入框 ──► JS 探测命中可编辑元素 ──► 打开 SDK 输入页
                                              （预填当前值）
用户输入完毕确认 ──► JS 写回 + 派发 input/change ──► 网页表单正常感知
```

配合一个前提：**WebView 自身被物理禁止拉起输入法**（连闪一下都不会），这是与其它「引导式」方案的本质区别。

## 3. 组件与文件

| 文件 | 职责 |
|---|---|
| `browser/tab/ImeBlockableWebView.kt` | WebView 子类。`blockIme=true` 时 `onCheckIsTextEditor()=false` 且 `onCreateInputConnection()=null`，输入法框架对该 View 彻底失效；默认 `false`，上游触屏 UI（DefaultBrowserActivity 等）行为完全不变 |
| `browser/tab/WebViewFactory.kt` | 改产 `ImeBlockableWebView`（返回类型仍是 `WebView`，pool / TabAdapter / TabPager 全链路无感知） |
| `keyphone/KeyphoneBrowserActivity.kt` | JS 模块注入、点击落点探测、打开 `KeydroidxTextInputFragment`、确认回填（见 §5） |
| `res/values/keyphone_strings.xml` | `keyphone_web_input_title`（输入页标题「输入内容」） |

## 4. JS 模块 `window.__keyphone_input__`

注入方式沿用本仓库惯例：`evaluateJavascript` + JSON 字符串回传（全仓无 `addJavascriptInterface`）。模块幂等安装（同 `__keyphone_copy__` 模板）。

- **监听**：`document` 上 capture 阶段的 `focusin` 与 `click`（不 stopPropagation，网页行为不受影响）；命中可编辑元素时记录 `el` 并置 `pending`。
- **可编辑元素判定 `editableOf()`**：`textarea`、`input`（type 白名单：text/search/email/url/tel/password/number/date/month/week/time/datetime-local）、`[contenteditable="true"|"plaintext-only"]`；排除 `disabled` / `readonly`。
- **`poll()`**：消费一次 `pending`，返回 JSON 字符串：
  `{focus: bool, value: string, multiline: bool, submit: bool}`——`multiline` 对 `textarea` / `contenteditable` 为 true；`submit` 表示确认回填后是否应模拟 Enter/提交表单（见下）。
- **`shouldSubmit(el)`**：对齐 Chromium 的 IME action 推断，决定按「确定」后是否自动执行搜索/提交：
  | 条件 | submit |
  |---|---|
  | `enterkeyhint` ∈ {search, go, send} | true |
  | `enterkeyhint` ∈ {next, done, enter}（写了其它值） | false |
  | `input[type=search]` | true |
  | textarea / contenteditable | false（Enter 语义是换行） |
  | 所在 form 内只有一个文本类输入（HTML 隐式提交条件，disabled/readonly 除外） | true |
  | 其他 | false |
- **`fill(text, submit)`**：写回 `el.value`（input/textarea）或 `el.textContent`（contenteditable），随后派发冒泡的 `input` 与 `change` 事件（页面脚本、表单校验可感知）；`submit=true` 时继续调 `submitEnter(el)`，返回 `{success}`。
- **`submitEnter(el)`**：模拟真实 Enter 按键——派发 `keydown`（key/code='Enter'，keyCode/which=13，cancelable）；若 `defaultPrevented`（SPA 监听 Enter 自行做无刷新搜索）则到此为止；否则补齐 `keypress`/`keyup`，且 `el` 在 form 内时触发提交：优先 `form.requestSubmit()`（会走 submit 事件 + 校验），老 WebView 无该方法时 fallback 为派发 cancelable 的 `submit` 事件（未被 preventDefault 再 `form.submit()`）。

### 注入时机

1. 进入网页态时，按 **「标签 id:URL」** 键去重预注入（`observeState`，导航/切标签后自动重注入）；
2. 每次光标确认键 **DOWN 时兜底注入**（幂等，防首击未装上）。

## 5. Activity 侧流程（KeyphoneBrowserActivity）

```
确认键 DOWN ─► 注入安装 JS + 派发触摸 DOWN
确认键 UP   ─► 派发触摸 UP ─► scheduleWebInputProbe()
120ms 后 poll（未命中则 300ms 重试，最多 3 次，容忍渲染慢的页面）
命中 ─► parseWebInputProbe()（JSONTokener 剥外层引号 → JSONObject）
     ─► 暂存 submit 标志（webInputPendingSubmit）
     ─► openWebInputEditor(value, multiline)
          预填 value 打开 KeydroidxTextInputFragment（multiline 时开多行，maxChars=0 不限）
     ─► setOnConfirmListener { fillWebInput(text, submit) }
          JSONObject.quote(text) 转义后调 fill(text, submit) 写回；
          submit=true 时 JS 侧继续 submitEnter()（模拟 Enter + 提交表单）
返回键/取消 ─► 不写任何内容
```

### 关键细节

- **探测取消**：退出网页态 / 弹快捷菜单 / 进查找或复制模式 / `onPause` 时 `cancelWebInputProbe()`；触摸序列严格 DOWN/UP 配对（`mouseTouchDown`），模式切换时补发 UP 防悬挂。
- **重复打开守卫**：`getCurrentPage() != null` 或处于查找/复制/菜单态时忽略探测结果。
- **重复点击已聚焦的框**：`click` 监听不依赖焦点变化，再点一次即可再次唤起输入页。
- **SDK 输入页契约**：`newInstance(title, text, hint, multiline, maxChars)`；`setOnConfirmListener` 同步回传文本（**注意 SDK 会 trim**）；无独立取消回调——BACK / 空内容 RSK 直接出栈不写回。

## 6. 已知边界

| 场景 | 行为 |
|---|---|
| 密码框 | 预填明文到输入页（按键机无遮蔽需求，如实测） |
| 首次点击极快（JS 安装竞态） | 本次点击不弹输入页（IME 也已被屏蔽，无副作用），再点一次即可 |
| 页面自动 focus 输入框（未点击） | 不弹输入页（仅点击触发探测），点击该框后可输入 |
| 搜索框无 `enterkeyhint`、非 `type=search`、非单输入 form | 不自动提交（Chromium 此场景 IME 也只显示回车箭头），输完移光标点页面搜索按钮 |
| 编辑期间页面导航 | `fill()` 检查 `document.contains(el)`，失效则静默放弃 |
| SPA 路由变化 | URL 变化 → 键去重失效 → 自动重注入（幂等） |
| select / checkbox / file 等非文本控件 | 不劫持，保持原生点击行为 |

## 7. 参数与调优

| 常量（KeyphoneBrowserActivity companion） | 默认值 | 说明 |
|---|---|---|
| `WEB_INPUT_PROBE_FIRST_MS` | 120ms | 确认键抬起后首探延迟 |
| `WEB_INPUT_PROBE_RETRY_MS` | 300ms | 未命中重试间隔 |
| `WEB_INPUT_PROBE_MAX_ATTEMPTS` | 3 | 总尝试次数（渲染慢的页面靠重试兜底） |

## 8. 测试要点

1. 带搜索框的页面：光标点击搜索框 → 应直接全屏输入页（无任何 IME 闪现）→ 输入确认 → 文字出现在框内并可触发搜索；
2. 预填：已有内容的输入框，打开输入页应带出原值；
3. textarea 多行：确认后换行符写入页面；
4. 点普通链接/按钮：不弹输入页，行为不变；
5. 表单校验：fill 后页面 JS 能收到 `input`/`change`（如登录表单按钮解锁）；
6. 快速连续点击两个不同输入框：分别打开对应输入页，值不串。
